# Model Card: Telco Customer Churn Prediction

## 1. Информация о модели
*   **Название модели:** Random Forest (predicting customer churn)
*   **Тип задачи:** Бинарная классификация (предсказание оттока)
*   **Разработчик:** Иванова Юлия
*   **Дата создания:** 2026
*   **Версия:** 1.0.0

## 2. Назначение и использование
*   **Основное назначение:** Предсказание вероятности того, что клиент телеком-компании прекратит пользоваться услугами (отток) в ближайшее время.
*   **Пользователи:** Маркетинговый отдел, отдел клиентского сервиса (Customer Success), менеджеры по удержанию.
*   **Контекст применения:** Модель используется для приоритизации клиентов, с которыми необходимо провести работу по удержанию (например, предложить персональную скидку или позвонить).

## 3. Входные и выходные данные
*   **Входные данные (Features):** Демографические данные (пол, возраст, наличие семьи), информация об услугах (тип интернета, онлайн-безопасность), данные о контракте (ежемесячная плата, срок действия контракта, общие расходы).
*   **Выходные данные (Target):**
    *   Вероятность оттока (от 0.0 до 1.0).
    *   Бинарный класс (1 — уйдет, 0 — останется) при пороге 0.5.
*   *Примечание:* Исходные категориальные признаки были закодированы (One-Hot Encoding), числовые — масштабированы (StandardScaler).

## 4. Используемые метрики качества
*   **ROC-AUC:** 0.844 (основная метрика, показывает способность модели ранжировать клиентов).
*   **Recall (полнота):** 0.775 (модель ловит 77.5% реальных уходов — критически важно для удержания).
*   **Precision (точность):** 0.547.
*   **F1-score:** 0.642.
*   *Обоснование:* Для бизнеса пропустить уходящего клиента (False Negative) дороже, чем ошибочно предложить скидку лояльному (False Positive). Поэтому использовался `class_weight='balanced'` для повышения Recall.

## 5. Ограничения (Limitations)
*   Модель обучена на исторических данных (до 2024 года) и может не учитывать новые тарифы или изменения на рынке.
*   Модель показывает корреляцию, но не доказывает причинно-следственную связь (мы не знаем *почему* клиент уходит, только *вероятность*).
*   Требует регулярного переобучения (например, раз в квартал) для предотвращения Data Drift.

## 6. Этические аспекты
*   Модель использует демографические данные (пол), что требует осторожности при принятии бизнес-решений, чтобы избежать дискриминации.
*   **Валидация:** Модель протестирована на отложенной тестовой выборке (20% данных), метрики подтверждены. Внедрение в бизнес-процесс должно сопровождаться A/B-тестом для подтверждения ROI (окупаемости).
